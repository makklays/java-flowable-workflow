1. What is the difference between == and .equals() in Java?

== compares references (memory addresses).
It checks whether two variables point to the same object.

.equals() compares values (content).
It checks whether two objects are meaningfully equal, according to the implementation of the equals() method.

2. Explain the concept of immutability. Why is String immutable?

Immutability means that once an object is created, its internal state cannot be changed.
If you modify it, you actually create a new instance.
String is immutable because:

Security
Strings are used in class loading, security keys, database URLs, file paths — immutability prevents tampering.
Thread-safety
Immutable objects are naturally thread-safe and require no synchronization.

String pool optimization
The JVM uses the String Pool to reuse String objects.
This works only because Strings cannot change.

Caching hashCode
Since a String never changes, its hashCode can be cached → faster Map/Set operations.

3. What are the main features introduced in the latest Java versions you’ve used?

A strong answer depends on your last Java version, но я дам универсальный ответ, который подходит для Java 11 → Java 21 (часто в банках).

Java 11
var can be used in lambda parameters.
New HTTP Client (non-blocking, async, HTTP/2).
Performance improvements to GC.

Java 17 (LTS — very common in banks)
Sealed classes.
Pattern matching for instanceof.
Records (data classes with minimal boilerplate).
Enhanced switch (switch expressions).
Strong encapsulation of JDK internals.

Java 21 (latest LTS)
Virtual Threads (Project Loom) — huge concurrency improvement.
Pattern matching for switch.
Sequenced collections.
String templates (preview).
Improved garbage collectors (ZGC, G1 improvements).

A perfect interview summary:
“The main features I used recently include Records for reducing boilerplate, pattern matching for cleaner control flow,
the new HttpClient for async communication, and Virtual Threads in Java 21 for highly scalable concurrency.”
