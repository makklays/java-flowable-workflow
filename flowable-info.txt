
BPMN:
- Start event
- End event
- Boundary event
- Exclusive
- Parallel
- Service Task
- User Task

CMMN (Case Management):
- Sentries
- Stages

API движка:
- RuntimeService (запуск)
- TaskService (работа с задачами)
- RepositoryService (деплой моделей)
- HistoryService (отчеты)

Task: User Task, Manual Task, Service Task, Script Task, Send/Receive Task, Business Rule Task, Global Task, Abstract Task.

ACT — это сокращение от Activiti (движок, на базе которого был создан Flowable), а префиксы после него обозначают категорию данных.
ACT_RU (Runtime) RU = RUntime (Время выполнения).
ACT_HI (History) HI = HIstory (История).
ACT_RE (Repository): REpository (Репозиторий). Здесь хранятся «шаблоны» ваших процессов — те самые XML-файлы (hello.bpmn20.xml), которые вы задеплоили. Они статичны.
ACT_GE (General): GEneral (Общие данные). Самая важная тут — ACT_GE_BYTEARRAY, где лежат бинарные данные ваших схем и ресурсов.
ACT_ID (Identity): IDentity (Личности). Здесь хранятся пользователи и группы, если вы используете встроенное управление пользователями Flowable.

Чтобы убедиться, что ваш XML-файл hello.bpmn20.xml успешно «проглочен» движком и превратился в исполняемый шаблон, выполните этот SQL-запрос в вашей MySQL-консоли:
SELECT ID_, KEY_, NAME_, VERSION_, DEPLOYMENT_ID_ FROM ACT_RE_PROCDEF;
В таблице ACT_RU_EXECUTION появится строка с состоянием вашего процесса.
В таблице ACT_RU_TASK появится строка с задачей "Одобрить отпуск".

Service Tasks: Научитесь писать Java-делегаты (JavaDelegate), которые выполняют бизнес-логику при переходе по шагам процесса.
Service Tasks: Изучите, как конфигурировать ProcessEngine через application.properties.
SQL: Потренируйтесь писать запросы для выгрузки статистики: сколько задач зависло, среднее время выполнения этапа.
Linux (Среда): поиск по логам (grep, tail -f), управление правами (chmod, chown), утилиты top, htop, netstat (проверка портов) и работа с Docker.

Практический план на 2 недели:
    Дни 1-3: Пройти туториал по BPMN 2.0. Скачать Flowable и запустить простой процесс через Java.
    Дни 4-7: Реализовать Service Task на Java, который записывает данные в Oracle через Spring Data JPA.
    Дни 8-10: Изучить обработку ошибок (Error Boundary Events) во Flowable и транзакционность.
    Дни 11-14: Развернуть свое приложение на виртуальной машине с Linux, настроить подключение к Oracle.

Что делать дальше (Level Up):
1. Углубление в Enterprise (Неделя 3-4):
    DMN (Decision Model and Notation): Изучите таблицы решений. Это когда логика «если сумма > 100к, то одобрить» выносится из Java-кода в Excel-подобные таблицы.
    Optimization: Изучите, как работают Async Jobs. Что делать, если задача должна выполняться в фоне и не вешать основной поток? Поймите концепцию job executor.
    Performance: Настройка индексов в Oracle для таблиц Flowable при миллионах записей.
2. Интеграционный слой:
    Научитесь интегрировать Flowable с Kafka или RabbitMQ. В реальных системах процессы часто запускаются сообщениями из очередей.
    Изучите Liquibase/Flyway для миграции схем БД Oracle вместе с кодом.
3. Тестирование:
    Освойте Flowable JUnit tests. Хороший спец пишет тесты, которые проверяют прохождение процесса по всем веткам без запуска всего приложения.
4. Выход на уровень Senior:
    Изучение исходного кода Flowable на GitHub.
    Проектирование отказоустойчивых кластеров (когда несколько серверов работают с одной БД Oracle).

Дальше — переход от «написания кода» к «проектированию систем» и управлению сложностью.
Когда вы освоите базу (Flowable + Java + SQL), ваш путь разделится на три мощных направления развития:
1. Уровень «Архитектор BPM-решений» (Architect)
Вы перестаете думать категориями «как написать этот Service Task» и начинаете думать, как построить систему, которая не упадет под нагрузкой:
    High Availability: Как запустить 5 экземпляров Flowable-приложения так, чтобы они не конфликтовали при доступе к одной БД Oracle.
    Performance Tuning: Оптимизация Oracle. Вы будете знать, какие индексы добавить в таблицы Flowable, когда там накопятся миллионы завершенных процессов (ACT_HI_*), чтобы отчеты не грузились по 5 минут.
    Multi-tenancy: Как сделать одну систему, в которой работают 10 разных дочерних компаний, не видя процессов друг друга.
2. Уровень «Enterprise Integrator» (Сложные связки)
BPM-движок никогда не живет в вакууме. Дальше вы учитесь связывать его со всем миром:
    Event-Driven Architecture: Запуск процессов не через API, а через события из Kafka или RabbitMQ. Например, пришла транзакция в банк — Flowable тут же подхватил её и запустил проверку безопасности.
    Микросервисная оркестрация: Использование Flowable как «дирижера», который вызывает десятки микросервисов, обрабатывает их отказы, делает повторные попытки (retries) и откатывает транзакции (Saga Pattern).
3. Уровень «Business Value & Process Mining» (Аналитика)
Это мост между IT и бизнесом. Вы учитесь извлекать выгоду из данных, которые накопились в Oracle:
    Process Mining: Использование данных из истории Flowable, чтобы показать бизнесу: «Смотрите, на этом этапе мы теряем 2 дня и 10% клиентов».
    BI-аналитика: Построение дашбордов (Grafana/Tableau) на основе SQL-запросов к таблицам Flowable для мониторинга эффективности сотрудников в реальном времени.

Итог: во что это превращается карьерно?
Через 1–2 года глубокой работы с этим стеком вы становитесь редким и дорогим специалистом.
Рынок перенасыщен обычными Java-разработчиками («пишу контроллеры и мапперы»), но специалистов, которые понимают логику
длинных бизнес-процессов, умеют их тюнить в Linux и оптимизировать в Oracle, — единицы.

Что нужно знать о Camunda (основные понятия):
    BPMN 2.0: Стандарт визуальных схем (стрелочки, квадратики, ромбики).
    Process Engine: Ядро, которое следит, на каком этапе сейчас находится процесс.
    Java Delegates: Классы, которые выполняются, когда процесс доходит до определенного «Service Task».
    External Tasks: Когда процесс ждет, пока сторонний сервис (например, твой фронт на Angular или React) заберет задачу и выполнит её.
    Cockpit / Tasklist: Готовые админки, где можно смотреть, где «застряли» процессы, и выполнять задачи вручную.

Сколько учить?
    База (2–4 дня): Установка Camunda 7 или 8, создание простого процесса «Hello World», привязка одного Java-класса.
    Рабочий уровень (2–3 недели): Обработка ошибок (Boundary Events), параллельные ветки, работа с переменными процесса и DMN (таблицы принятия решений).
